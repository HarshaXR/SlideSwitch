# SlideSwitch Protocol v1

One protocol, used by the Android remote and both companions (macOS, Windows).

## Transport

| Item | Value |
|---|---|
| Transport | WebSocket (RFC 6455), text frames, UTF-8 JSON |
| Default port | `48620` (TCP). Companions fall back to any free port if taken; the real port is in the Bonjour/mDNS record and the QR code |
| WebSocket path | `/` (servers must accept any path) |
| Discovery | DNS-SD / mDNS service type **`_slideswitch._tcp`**, instance name = the computer's name |
| TXT record | `v=1`, `platform=macos` or `windows`, `id=<stable server UUID>` |

Every message is a JSON object with a string `type`. **Receivers must ignore unknown fields,
and must ignore (or answer with `error`/`unsupported_type`) unknown message types.** This is
the main extensibility rule: new features add new `type`s or new `action`s, never change the
meaning of existing ones.

## Pairing

The companion shows a **6-digit pairing code** (regenerated each launch, and on demand) and a
QR code containing a deep link:

```
slideswitch://pair?host=192.168.1.20&port=48620&code=482913&name=Harsha%27s%20Mac
```

Scanning the QR with the phone's camera opens the Android app pre-filled. The phone can also
discover the companion over mDNS, or the user can type the IP and port.

After the first successful pairing the server returns a **token**. The phone stores it per
server `id` and sends it instead of a code next time, so reconnects don't need the code.
Tokens are remembered by the companion until the user clicks “Forget paired devices”.

## Session flow

```
phone                                   companion
  | --- WebSocket connect --------------> |
  | --- hello {code | token} -----------> |
  | <-- welcome {token, capabilities} --- |   (or error + close)
  | --- command {id, action} -----------> |
  | <-- ack {id, ok} -------------------- |
  | --- ping ---------------------------> |   (every 10 s; server may drop after 30 s silence)
  | <-- pong ---------------------------- |
```

The server must reject any message except `hello`/`ping` before a successful `hello`.

## Messages: phone → companion

### `hello`
```json
{ "type": "hello", "v": 1, "device": "Pixel 9", "deviceId": "6f1c…", "code": "482913" }
```
or, when re-connecting, `"token": "…"` instead of `"code"`. `deviceId` is a stable random
UUID generated by the phone.

### `command`
```json
{ "type": "command", "id": "c-17", "action": "next" }
```
`id` is chosen by the phone and echoed in the `ack`. Optional `args` object for future actions.

| `action` | Meaning | macOS keys | Windows keys |
|---|---|---|---|
| `next` | Next slide / build | → | → |
| `previous` | Previous slide | ← | ← |
| `start` | Start presentation | Keynote ⌥⌘P · PowerPoint ⇧⌘↩ · other (e.g. Google Slides) ⌘↩ | F5 (PowerPoint) · Ctrl+F5 if a browser is focused (Google Slides) |
| `end` | End presentation | Esc | Esc |
| `black` | Toggle black screen | B | B |

Keys go to the frontmost app, so the presentation app must be focused.

### `ping`
```json
{ "type": "ping" }
```

## Messages: companion → phone

### `welcome`
```json
{
  "type": "welcome", "v": 1,
  "server": "Harsha's Mac", "serverId": "0b5e…", "platform": "macos",
  "token": "…",
  "capabilities": ["next", "previous", "start", "end", "black"]
}
```
The phone should only show controls whose action is in `capabilities`.

### `ack`
```json
{ "type": "ack", "id": "c-17", "ok": true }
```

### `error`
```json
{ "type": "error", "id": "c-17", "code": "unsupported_action", "message": "…" }
```

| `code` | When | Connection |
|---|---|---|
| `bad_code` | wrong pairing code / unknown token | closed by server |
| `not_paired` | command before successful `hello` | closed by server |
| `unsupported_action` | unknown `action` | stays open |
| `unsupported_type` | unknown `type` | stays open |
| `bad_message` | invalid JSON / missing fields | stays open |
| `permission_denied` | the OS refused key injection (e.g. macOS Accessibility not granted) | stays open |
| `version` | incompatible `v` | closed by server |

### `pong`
```json
{ "type": "pong" }
```

### `status` (optional, any time)
```json
{ "type": "status", "frontApp": "Keynote" }
```
Informational; phones may display it or ignore it.

## Versioning

`v` is the protocol major version. Additive changes (new actions, new optional fields, new
message types) keep `v: 1`. A server receiving a higher `v` it can't speak replies
`error`/`version` and closes.

## Security notes (v1)

Local network only, no TLS. The pairing code limits who can drive the computer; the server
closes the connection after a wrong code and should rate-limit failed attempts (companions
lock out an address for 5 s after 3 failures).
